== Overview
This document defines the technical architecture, tools, frameworks, and dependencies for the Zitate web-based single-page application (SPA).

== Technology Stack

=== Primary Technologies
- *Platform:* Web (Desktop and Mobile Browsers)
- *Language:* TypeScript ES2020+
- *UI Framework:* React 18
- *Build Tool:* Vite 7
- *Package Manager:* npm
- *Local Database:* PouchDB (IndexedDB-backed, replaces raw `idb` wrapper)
- *Remote Database:* CouchDB (self-hosted, per-user database isolation)

=== Core Browser APIs
- *IndexedDB:* Used internally by PouchDB for local persistence
- *Service Worker:* Offline capability and PWA
- *Geolocation API:* GPS coordinates
- *MediaRecorder API:* Audio recording
- *MediaDevices API:* Camera access
- *File API:* Image upload

== Architecture Pattern

=== Component-Based Architecture
- *Components:* Reusable React UI components
- *Hooks:* Custom React hooks for shared logic and state management
- *Services:* Singleton business logic services (db.service, location.service)
- *Models:* TypeScript interfaces for type safety

=== State Management
- *Local State:* Component state (useState)
- *Persistent State:* PouchDB (IndexedDB-backed) via custom hooks (useEntries, useAuthors, useLabels, useFolders)
- *Cross-instance sync:* PouchDB change feed (`db.changes({ live: true })`) replaces the custom storeSync event emitter
- *Remote sync:* PouchDB bidirectional replication to CouchDB (live, retry)
- *Derived State:* Computed values from PouchDB queries (useCallback, useMemo)

=== Data Flow

[source]
----
User Interaction → Component → Hook → DBService → PouchDB (local)
                    ↑                                 ↓    ↕
                    └────── Change Feed ←────────────┘  CouchDB (remote)
----

== PouchDB Document Model

=== Database Configuration
- *Local Database:* PouchDB with IndexedDB adapter (browser default)
- *Remote Database:* CouchDB, one database per authenticated user
- *Replication:* Bidirectional, live, with retry
- *Migration:* Existing `idb`-based IndexedDB data is migrated to PouchDB on first launch after upgrade

=== URL Attachment and Favicon Handling

Attached URLs are managed as embedded `EntryLink` objects on the `Entry` record.

==== Entry Form Behavior
- Entry form provides add/remove controls for multiple URLs
- Each URL is validated using the browser `URL` constructor before save
- Each newly added URL receives a generated `id` and `addedAt` timestamp
- `citationDate` is initialized to the entry creation date and may be edited independently

==== Favicon Resolution Strategy
- Favicon is derived at render time from the URL origin, typically `<origin>/favicon.ico`
- Favicon URLs are not persisted in IndexedDB because they are derivable from the attached URL
- If favicon loading fails, the UI falls back to a bundled default favicon asset
- Favicon loading failure must not block rendering of the attached URL list

==== Entry Card URL UI
- Entry cards render a dedicated link icon in the top-right area of the text block when `links.length > 0`
- Activating the icon opens a compact dropdown or popover containing all attached URLs
- Each row shows favicon, URL label/text, and the stored per-link attachment date
- The URL list must be keyboard accessible and support mouse and touch interaction
- Selecting a URL opens it in a new browser tab/window using standard browser navigation

=== Image Editing in Entry Edit Mode
When editing an existing entry, the user must be able to manage attached images with the following operations:

==== Add Images
- Same upload flow as entry creation (file picker, validation, compression)
- New images are compressed and stored in IndexedDB `images` store
- Entry's `imageIds` array is updated with the new image IDs
- Respects the max 10 images per entry limit (existing + new)

==== Delete Images
- Each existing image thumbnail shows a delete button (×)
- Deleting removes the image from IndexedDB `images` store
- Entry's `imageIds` array is updated to remove the deleted ID
- Immediate UI feedback

==== Reorder Images (Sort)
- Drag-and-drop or move-up/move-down buttons on thumbnails
- Updates the `order` field on each `ImageAttachment` in IndexedDB
- Updates the `imageIds` array order on the `Entry`

==== Update Images (Replace)
- User can click a "replace" action on an existing thumbnail
- Opens file picker for a single image
- Old image is deleted from IndexedDB, new one is stored
- Entry's `imageIds` array is updated (same position)

=== Synchronization Service

==== Architecture

[source]
----
PouchDB (local)  ←──  bidirectional live replication  ──→  CouchDB (remote)
       ↓                                                          ↑
  Change Feed                                               Per-User DB
       ↓                                                    (userdb-<hex>)
  Hook Reload
----

==== Sync Lifecycle

[source,typescript]
----
class SyncService {
  private replication: PouchDB.Replication.Sync<{}> | null = null;

  /** Start live bidirectional sync to remote CouchDB */
  startSync(localDb: PouchDB.Database, remoteUrl: string): void;

  /** Stop active replication */
  stopSync(): void;

  /** Get current sync status */
  getStatus(): SyncStatus;

  /** Register listener for sync status changes */
  onStatusChange(callback: (status: SyncStatus) => void): () => void;

  /** Scan for conflicting revisions and create duplicate documents */
  resolveConflicts(): Promise<ConflictResolutionResult>;
}

type SyncStatus = 'idle' | 'syncing' | 'paused' | 'error' | 'offline';

interface ConflictResolutionResult {
  resolved: number;
  duplicatesCreated: string[];  // IDs of newly created duplicate documents
}
----

==== Conflict Resolution Strategy
- PouchDB/CouchDB automatically tracks conflicting revisions via the `_conflicts` flag
- After each sync cycle, the `SyncService` scans for documents with `_conflicts`
- For each conflicting document, the losing revision is extracted, given a new `_id`, and stored as a separate document
- The winning revision remains at the original `_id`
- Both documents are marked with a `conflictSource` field pointing to each other's ID
- The UI displays a visual indicator (⚠️) on conflicting entries
- The user resolves conflicts manually by editing or deleting one of the duplicates

==== Per-User Database Isolation
- CouchDB uses the database-per-user pattern
- Each authenticated user gets a database named `userdb-<hex-encoded-username>`
- The CouchDB `couch_peruser` plugin automatically creates databases on user registration
- PouchDB replicates only between the local database and the user's remote database

== Performance Optimization

=== IndexedDB
- Indexes on frequently queried fields (createdAt, name, etc.)
- Cursor-based pagination for large result sets
- Batch operations for multiple inserts/updates
- Transaction management (readwrite vs readonly)

=== UI
- Virtual scrolling for lists >100 items (react-window, vue-virtual-scroller)
- Lazy loading images (IntersectionObserver)
- Debounced search (300ms)
- Code splitting by route (React.lazy, dynamic imports)
- Memoization for expensive computations (useMemo, computed)

=== Bundle Size
- Tree shaking (Vite/Webpack)
- Dynamic imports for heavy features (maps, image compression)
- Minification and compression (gzip/brotli)
- Target: <500KB initial bundle (gzipped)

== Security and Privacy

=== Data Protection
- All data stored locally in browser (PouchDB/IndexedDB) by default
- Server communication only when user opts in to sync (authenticated session)
- Data transmitted over HTTPS only
- Per-user database isolation on CouchDB (no cross-user data access)
- No cookies or tracking beyond authentication session
- Content Security Policy (CSP) headers

=== Authentication
- CouchDB `_users` database for user management
- Session-based authentication with HTTP-only cookies or bearer tokens
- Password stored as bcrypt hash on CouchDB server
- Session expires after configurable timeout
- Logout clears session token from browser

=== Input Validation
- Client-side validation for all user inputs
- XSS prevention (sanitize HTML, use framework escaping)
- SQL injection N/A (no SQL database)

=== Permissions
- Geolocation: Requested with user-friendly prompt
- Camera: Requested on first image capture
- Microphone: Requested on first audio recording
- Storage: Automatic with quota management

== Technical Risks and Mitigations

=== Risk: IndexedDB Quota Limits
- *Mitigation:* Monitor storage usage, provide export before limits reached, warn user

=== Risk: Browser Compatibility Issues
- *Mitigation:* Feature detection, graceful degradation, clear browser requirements

=== Risk: Data Loss
- *Mitigation:* Automatic export prompts, periodic backup reminders, import/export functionality

=== Risk: Performance with Large Datasets
- *Mitigation:* Virtual scrolling, pagination, IndexedDB cursors, lazy loading

=== Risk: Media Storage Limits
- *Mitigation:* Image compression, size limits, warn before adding large files

=== Risk: PouchDB Migration Data Loss
- *Mitigation:* One-time migration reads old `idb` stores and writes to PouchDB before deleting old data. Export backup prompted before migration.

=== Risk: Sync Conflicts Overwhelming Users
- *Mitigation:* Clear visual indicators for conflicts, simple merge/delete workflow, automatic resolution for non-ambiguous changes (e.g., only one side modified)

=== Risk: CouchDB Availability
- *Mitigation:* App remains fully functional offline. Sync is optional and resumes automatically when CouchDB becomes available again.
